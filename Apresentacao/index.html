3. ResNet
Rede Neural Profunda
→
4. Embedding
Vetor 128D

O que é um Embedding?

É uma lista de 128 números que representam as características únicas de um rosto. Rostos da mesma pessoa geram números próximos matematicamente.

Cálculo de Distância

distancia = euclidean(face1, face2) match = distancia < 0.6

Se a distância Euclidiana for menor que 0.6, consideramos que é a mesma pessoa.

Como Funciona: DeepFace

O Validador Robusto

Um framework que unifica modelos de estado da arte (VGG-Face, Google FaceNet, ArcFace).

Características

  • Modelo Usado: Facenet (Google).
  • Dimensão: 128 números por rosto (igual ao FR).
  • Métrica: Similaridade de Cosseno.
  • Vantagem: Mais robusto a variações de iluminação e ângulo.

Por que é mais lento?

A rede neural é muito mais profunda e complexa. Enquanto o face_recognition foca em velocidade (CPU friendly), o DeepFace brilha com aceleração de GPU (que não utilizamos no servidor padrão para manter custos baixos).

Sistema Híbrido (Estratégia SMART)

Lógica de Decisão Inteligente

Para mitigar as fraquezas individuais, implementamos um algoritmo de decisão em cascata:

Fluxo de Decisão

  1. Executa face_recognition (Rápido).
  2. Verifica o nível de confiança.
  3. Alta (>55%): Aceita imediatamente. ✅
  4. Média (35-55%): Chama DeepFace para validar. 🔄
  5. Baixa (<35%): Usa DeepFace como autoridade. ⚠️
  6. Se falhar: DeepFace Fallback.

Thresholds Definidos

55.0%
High Confidence Threshold

Acima disso, o face_recognition raramente erra. Otimiza velocidade.

35.0%
Low Confidence Threshold

Abaixo disso, o resultado é incerto e requer validação cruzada.

Dificuldades: Instalação e Ambiente

O Desafio do dlib no Windows

Problema: A biblioteca face_recognition depende do dlib, que é escrito em C++. O pip install falha no Windows por falta de compiladores nativos.

Solução Implementada

  1. Instalação do Visual Studio Build Tools (Compilador C++).
  2. Instalação e configuração do CMake no PATH do sistema.
  3. Compilação manual do dlib antes de instalar o pacote Python.
  4. Uso de arquivos .whl (wheels) pré-compilados para agilizar o setup em novas máquinas.

Dificuldades: Banco de Dados

Migração SQLite → Supabase

SQLite
Inicial
  • Arquivo local (.db)
  • Bloqueio de escrita (concorrência ruim)
  • Difícil de compartilhar entre devs
Supabase
Final
  • PostgreSQL na nuvem
  • API REST nativa
  • Suporte a tipos complexos (Arrays/JSON)
  • Escalabilidade real

Desafio Técnico

Adaptar o ORM SQLAlchemy para trabalhar de forma otimizada com o PostgreSQL, especialmente no armazenamento dos vetores de embedding (arrays de float) que precisaram ser serializados corretamente.

Evolução do Frontend

React Local
Robusto/Rápido

Inicialmente tentamos usar ferramentas No-Code (Lovable) conectadas via túnel (Ngrok) ao backend local. Isso gerou latência alta e falhas de conexão.

Solução Definitiva: Reescrever o frontend em React puro rodando localmente, comunicando-se diretamente com o backend via localhost, eliminando intermediários e garantindo resposta instantânea.
